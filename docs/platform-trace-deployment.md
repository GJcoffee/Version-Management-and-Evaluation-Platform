# 平台部署与 Trace 配置指南

本指南说明平台的通用部署、接入迁移和 Trace 配置流程。账号正文、业务配置导出、
会话记录、运行统计、数据库副本和现场部署回执保存在本地私有目录，不进入仓库。

## Docker 部署

标准 Dockerfile 构建完整后端、数据库迁移与前端产物。npm 和 pip 使用 BuildKit 缓存；
需要其他包源时，通过构建参数 `NPM_REGISTRY` 和 `PIP_INDEX_URL` 指定。

部署前设置以下环境变量，实际值由部署者在本机维护：

| 变量 | 用途 |
| --- | --- |
| `EVALP_MACHINE_ID` | 密钥库使用的固定机器标识 |
| `EVALP_SECRET_USER` | 密钥库使用的固定用户名，传入容器的 `USER` |
| `EVALP_HOME` | 宿主机数据目录，默认 `~/.evalp` |
| `EVALP_IMAGE` | 本次构建、部署使用的镜像标签 |
| `EVALP_ARTIFACTS_ALLOWED_HOSTS` | 允许抓取 JSON 产物的域名列表 |

`EVALP_MACHINE_ID` 与 `EVALP_SECRET_USER` 必须与现有密钥库一致，容器重建时保持不变。
新库也应固定这两个值。Compose 在缺少任一值时拒绝启动。

本地配置文件可存放在 `.private/deploy.env`。该目录被 Git 和 Docker 排除；
使用已有库时填写已有身份，镜像标签由部署者为本次发布指定。

```bash
docker compose --env-file .private/deploy.env build
docker compose --env-file .private/deploy.env up -d --no-build
docker compose --env-file .private/deploy.env logs --tail 80
```

每次发布使用独立镜像标签，并保留上一镜像用于回滚。容器只映射
`127.0.0.1:7860`。数据目录与本机 CLI / MCP 共用时，只启动一个服务进程。

## 数据库迁移与接入兼容

服务启动时执行数据库迁移。部署前停止写入，备份数据库与匹配的加密密钥库，
并在隔离副本中验证升级；业务数据副本始终存放在仓库排除的私有目录。

相关迁移的功能范围：

| 迁移 | 平台功能 |
| --- | --- |
| `0011` | 桥接 Trace 与用时记录 |
| `0012` | 多平台测试、生产环境配置 |
| `0013` | 历史版本的有效适配器路由与接入迁移审计 |
| `0014` | 平台账号与不可变登录态修订 |
| `0015` | 评测逐轮中间件计划 |

旧 `{id, version}` 绑定可以兼容读取，新绑定使用
`{adapter, major, config, credential_ref}`。配置存档和会话快照保存连接配置，
适配器实现由平台统一维护。

历史接入迁移先通过 MCP `migrate_adapter_bindings` 或
`POST /adapters/binding-migrations` 预览，核对对象后再应用。
版本的原 Spec 与内容 hash 保留，有效接入由 `version_adapter_routes` 单独记录；
迁移前配置及变更审计通过 `get_adapter_binding_migration` 或对应 REST 接口查询。

依赖旧桥逻辑或录制数据的历史版本须先发布并核实原生内容。
未完成核实时，执行返回 `NATIVE_DEPLOYMENT_REQUIRED`，避免将当前生产内容当作历史版本运行。
已保存原消息身份的历史轮次仍可重查 Trace；存在多个候选身份时拒绝猜测。

## Trace 账号与凭据

在设置 → 适配器 → HiAgent → Trace 账号中添加站点、租户（可选）、用户名和密码。
密码与完整 Cookie / CSRF 存在 SecretStore 的加密正文中，数据库保存引用与修订，
接口不回显秘密正文。编辑时密码留空表示保留现有密码，更新密码后旧登录态失效。

先在测试配置中选择同站点的 Trace 账号，检查上游认证，保存后推送生产。
绑定只保存 `observe_account_ref`；发布 API Key 独立维护。
未选择账号的旧绑定仍可使用凭据中的 `observe_headers`。

账号支持检查、重登、停用和补充人工登录态。首次 Trace 补齐与旧轮次重查共用最新登录态；
认证失效时尝试重登，只读查询最多重放一次。权限错误不会循环登录，
密码或额外验证失败时等待人工恢复。账号停用保留历史修订。

## Trace 重查与指标

轮次结束后，远端 Trace 在后台补齐。旧轮次可使用“重新获取 Trace”入口，
选择原配置或平台最新配置、生产或测试环境及凭据。
MCP `refresh_trace` 的 `force=true` 可重查已标记完整的缓存。

重查更新观测事件与指标，并记录配置、凭据引用、原消息身份、实现指纹和查询结果。
原输入、输出、执行状态、业务中间件快照与起止时间保持不变；
强制重查失败时保留已取得的完整结果，失败原因写入查询审计。

统一 HiAgent 实现将有效非负整数和数字字符串归一化后统计 token，
区分核心模型调用与包装 span，避免重复计数。规范用时使用已取得的远端指标；
缺失、非法值和未就绪状态保持未知，不能用本地测量或零值代替。

## 评测逐轮中间件

评测配置可保存从轮号 1 开始的 `turn_middlewares` 计划，
数据集 `input.turn_middlewares` 可按轮覆盖。
输入处理器使用本次会话上一轮的成功输出，输出处理器校验本轮阶段契约。

某轮处理失败时停止该用例并保留错误和步骤，其他用例继续。
自动及手动重试均新建会话；计划参与缓存键，重评分不重新执行业务。
Web、REST、MCP `run_eval` 和 CLI 配置文件均可使用该功能。

## 验证与回滚

部署后检查服务健康、迁移版本、运行包和静态页面，
并核对数据库完整性、外键及升级前已有数据。平台功能验证使用合成样例；
现场认证结果、配置回包与业务运行数据留在私有目录。

回滚前确认旧镜像能够识别当前数据库迁移版本。
`0013` 已有迁移审计或 `0014` 已有账号时，迁移会拒绝丢弃数据的降级。
未经兼容处理的旧镜像不能直接启动在较新的数据库上。

需要恢复升级前完整状态时，先停服务并另存当前数据，
再配合升级前数据库、匹配的密钥库和旧镜像恢复。
完整恢复会回退升级后的数据；普通代码回滚应优先使用兼容当前数据库的镜像。
