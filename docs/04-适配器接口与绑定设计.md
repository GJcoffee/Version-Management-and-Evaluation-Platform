# 适配器接口与绑定设计

> 状态：设计稿，待评审
> 日期：2026-11-11
> 范围：平台侧适配器抽象、绑定数据、Trace 重查、业务逻辑出栈与迁移步骤。不涉及具体业务提示词。

## 1. 结论摘要

适配器收敛为“一个平台一个实现、一个平台一个大版本”，实现由平台统一维护；绑定只保存连接配置和凭据引用，不再保存适配器实现版本。

三条硬边界：

1. 适配器只做协议翻译，入口只有 `probe` / `run_turn` / `refresh_trace` 三个，输出统一走事件归一化。
2. 业务逻辑（阶段校验、JSON 消费、AB 对比、输出契约）不得进入适配器包，由中间件 / 评估器 / 契约模块承担。
3. 禁止运行时补丁。适配器变更必须走“改实现 + 契约测试 + 随平台发布”。

复杂度不会消失：HiAgent 的 SSE 复用 think ID、Trace 拓扑、层级 token 仍然存在，但只允许存在于一个模块和一套契约测试里。

## 2. 迁移前盘点（历史）

当前仓库里同时存在多份 HiAgent 协议实现：

| 位置 | 职责 | 问题 |
|---|---|---|
| `backend/evalp/runtime/adapters/hiagent_adapter.py` | 平台原生 SSE / 用量 / 工具映射 | 与桥接实现重复 |
| `backend/evalp/runtime/adapters/hiagent_trace.py` | Trace 查询与补齐 | 只服务原生适配器 |
| `integrations/hiagent/bridge.py` | SDK 版发布 API 桥 | 又一份 SSE 解析，业务运行依赖它 |
| 业务侧 `event_mapper.py` / `live_runtime.py` / `local_runtime.py` | 业务桥的阶段、AB、消费器 | 协议 + 业务 + 运行补丁混在一起 |
| 业务侧 `patches/*.py` | 运行时替换函数 | 无版本可追溯，只能靠人记 |
| `releases/1.1.x` | 每个版本一套包 | 按版本复制，修一处要发多次 |

绑定层的固化问题：

- `AdapterBinding` 带 `id` + `version`（`backend/evalp/spec/models.py`），前端按 `id@version` 选择，等于把实现版本钉死到每个绑定。
- `validate_binding` 写死只接受 `("hiagent", "1.0.0")`（`backend/evalp/runtime/adapters/registry.py`），升级只能换绑或改代码。
- 会话创建时把整个 `binding` 冻结进 `adapter_snapshot`（`backend/evalp/services/session.py`），平台升级后历史绑定不会跟随。
- Trace 重查逻辑依赖“原生适配器 + 会话快照里有 binding”；桥接会话没有 binding，就永远无法重查。

## 3. 目标与非目标

目标：

- 一个平台只有一个活跃适配器实现；平台升级一次，所有绑定立即生效。
- 绑定只表达“连到哪个平台、哪个应用/版本、用哪份凭据”。
- Trace 重查成为适配器能力，而不是每类业务会话各写一套。
- 业务胶水从适配器/桥里搬走，且能被架构测试阻止回流。

非目标：

- 不追求跨平台统一业务语义；业务差异留在中间件/评估器。
- 不为历史会话保留旧适配器实现副本；只记录指纹用于审计。
- 不引入按 agent 版本绑定适配器的能力。

## 4. 分层与概念模型

```
            ┌──────────────────────── 平台层 ────────────────────────┐
            │ Runner / EventSink / 归一化 / 会话与评测调度             │
            └───────────────▲─────────────────────────────────────────┘
                            │ 规范事件 + 统一指标口径
            ┌───────────────┴─────────────────────────────────────────┐
            │ PlatformAdapter（每平台一个实现，平台代码统一升级）       │
            │  openai@1        hiagent@1        agentkit@1             │
            └───────────────▲─────────────────────────────────────────┘
                            │ 绑定配置 + 凭据引用
            ┌───────────────┴─────────────────────────────────────────┐
            │ AdapterBinding（连接配置，不含实现版本）                  │
            │  环境存档（production / test）→ 会话快照 → 轮次指纹       │
            └─────────────────────────────────────────────────────────┘
```

概念定义：

- **PlatformAdapter**：某个平台协议的唯一实现，带 `adapter`（平台 id）与 `major`（大版本）。
- **AdapterBinding**：连接配置。字段为 `adapter`、`major`、`config`、`credential_ref`，不含实现版本。
- **Capability**：适配器声明的能力，如 `streaming`、`tools`、`trace`、`refresh_trace`、`usage`。
- **AdapterFingerprint**：`adapter + major + impl_digest + config_fingerprint`。`impl_digest` 为适配器包内源文件的排序哈希，启动时计算。
- **Contract fixture**：每个平台脱敏后的真实 SSE / Trace 片段，作为适配器契约测试输入与期望规范事件。

## 5. 适配器接口契约

### 5.1 注册元数据

```python
class AdapterDefinition(BaseModel):
    adapter: str                 # "hiagent" | "openai" | "agentkit" ...
    major: int                   # 只有平台 API 不兼容才 +1
    name: str
    api_versions: list[str]      # 支持的平台 API 版本（写进绑定 config / 探测结果）
    capabilities: list[str]
    config_schema: dict          # 绑定配置的 JSON Schema
    impl_digest: str             # 适配器包源码哈希
    sunset: str | None = None    # 旧大版本下线日期；活跃大版本必须为 None
```

`GET /adapters` 只返回活跃实现；旧大版本仅在只读查询接口里可见，并带 `sunset`。

### 5.2 Python 协议

```python
class PlatformAdapter(ABC):
    adapter: ClassVar[str]
    major: ClassVar[int]
    capabilities: ClassVar[frozenset[str]]
    config_model: ClassVar[type[BaseModel]]

    def __init__(self, binding: NormalizedBinding, ctx: AppContext) -> None: ...

    async def probe(self) -> HealthResult:
        """只读检查：配置、凭据、身份；不发起会产生副作用的业务请求。"""

    def run_turn(
        self, ctx: RunContext, history: list[Message], user_input: Message,
    ) -> AsyncIterator[AgentEvent]:
        """执行一轮，产出规范事件；不写 turn.start / turn.end（Runner 负责）。"""

    async def refresh_trace(
        self, request: TraceRefreshRequest,
    ) -> AsyncIterator[AgentEvent]:
        """重查当前轮 Trace；默认抛 CapabilityUnavailable("refresh_trace")。"""

    async def aclose(self) -> None:
        """释放连接、子进程或流。"""
```

`build_adapter` 不再按 `transport` 分支判断“是不是 HiAgent”，而是：

1. 取会话快照里的 `binding`（没有则回退到 ConfigSpec / CodeSpec 的本地运行方式）；
2. `registry.resolve(binding.adapter, binding.major)`；
3. 构造 `PlatformAdapter`，把 `binding`、凭据、`AppContext` 传进去。

OpenAI 兼容平台同样走这套接口；`CodeSpec.transport=http|subprocess` 保留给完全自定义的 agent，不参与平台适配器体系。

### 5.3 广告与能力

- `probe` 仅允许做无副作用的读操作：身份、版本、观测地址可达性。
- `run_turn` 必须声明本轮指标是否为远端口径：若设置 `ctx.late_observe`，则轮次结束时本地用时只写入 `usage.local_*`，规范用时留空。
- `refresh_trace` 仅当 `refresh_trace in capabilities` 时可被调用；否则平台返回 `CAPABILITY_UNAVAILABLE`。

### 5.4 事件归一化

适配器只能产出以下事件类型，且必须满足：

| 事件 | 约束 |
|---|---|
| `llm.request` / `llm.response` | `step_id` 在轮内唯一；`llm.response.usage` 只描述该次调用；`finish_reason` 可缺省 |
| `tool.call` / `tool.result` | 以 `call_id` 关联；`tool.result` 必须带 `is_error`；不重复发送同一 `call_id` |
| `llm.reasoning` | 只作为展示，不参与次数与 token 统计 |
| `metrics` | 整轮指标只允许一个来源为权威：`source` 明确 `hiagent_trace` / `adapter_sse` / `provider_usage` |
| `error` | 使用统一 `{code, message, retriable}`；未知上游错误不得伪造成功 |
| `log` | 仅诊断；不得作为指标来源（业务桥历史兼容除外，见 8.3） |

统一口径（平台层只实现一次）：

- `prompt_tokens` / `completion_tokens`：整轮 token 与明细 token 不得双重累计；整轮优先，明细只补空缺。
- `llm_calls`：按 `llm.response` 去重计数；没有响应的事件流标记 `llm_calls_status="unknown"`。
- `tool_calls`：按 `(step_id, call_id)` 去重；仅 SSE 展示、未完成的不计入。
- 用时：远端可取得时只使用远端 `upstream_run_ms`；本地测量只写 `local_latency_ms` / `local_ttft_ms`。
- Trace 状态：`pending` → `complete` / `partial` / `unavailable`，同一轮只允许单调前进。

适配器不得自行拼装 `turn.end` 的用量汇总；汇总由 Runner 的 `_usage` 统一完成。

### 5.5 错误与取消

```python
class AdapterError(Exception):
    code: str          # AUTH / PROTOCOL / UPSTREAM_ERROR / RESULT_UNKNOWN / CAPABILITY_UNAVAILABLE
    message: str
    retriable: bool
```

- 认证失败、协议字段缺失、上游明确失败：不可重试，直接 `error`。
- 网络断开、上游 5xx、Trace 尚未生成：可重试；是否重试由平台策略决定，适配器只报告事实。
- 取消：适配器必须在 `finally` 释放资源；不得吞掉 `CancelledError`。

## 6. 绑定数据结构

### 6.1 新结构

```json
{
  "adapter": "hiagent",
  "major": 1,
  "config": {
    "base_url": "https://hiagent.example",
    "app_id": "app_xxx",
    "user_id": "u_xxx",
    "published_version": "1.0.0",
    "observe_base_url": "https://hiagent.example",
    "observation_wait_s": 15,
    "api_version": "2025-05-01"
  },
  "credential_ref": "adapter:prv_xxx"
}
```

规则：

- `adapter` + `major` 决定实现；`config` 决定连接到哪个应用/版本。
- agent 的发布版本只是 `config.published_version`，不是适配器版本。
- `credential_ref` 仍为不可变引用；换凭据产生新引用，历史轮次保留旧指纹。
- `api_version` 只表达平台 API 版本；适配器实现内部按它选择兼容分支，禁止按 agent 版本分支。

### 6.2 兼容读取旧结构

旧数据可能是：

```json
{"id": "hiagent", "version": "1.0.0", "config": {...}, "credential_ref": "..."}
```

读取时归一化：

```python
adapter = raw.get("adapter") or raw["id"]
major = raw.get("major") or int(str(raw.get("version", "1.0.0")).split(".")[0])
```

- 存储层不重写历史存档，避免改变审计与指纹；新写入一律使用新结构。
- `AdapterBinding.version` 从 Pydantic 模型删除；旧字段只在兼容校验器里接受并丢弃。
- `validate_binding` 不再写死 `("hiagent", "1.0.0")`，改为查注册表；找不到 `(adapter, major)` 时返回明确的下线/不存在错误。

### 6.3 环境、快照与更新

- 环境存档（`adapter_environments` / `adapter_environment_revisions`）结构不变，`binding` 存新 JSON。
- 会话创建时快照只冻结 `binding`（连接配置）与 `config_fingerprint`，**不冻结实现版本**。
- 轮次开始时记录 `adapter_fingerprint`（含 `impl_digest`）到 `usage` 与 `metrics` 事件，用于审计与复现。
- 平台升级适配器后：
  - 新轮次立即使用新实现；
  - 正在执行的轮次继续用已加载对象；
  - 历史轮次重查 Trace 时使用当前实现；默认以最新平台配置替换凭据和允许更新的观测字段，
    原应用、版本、workspace 和 message_id 保留，原快照不修改。
- 评测批次在创建 `eval_run` 时把 `adapter_fingerprint` 写入 `run.adapter_snapshot`，该批次所有 Item 固定使用这一指纹；批次进行中升级平台不改变该批次实现（Runner 仍执行当前代码，但结果会标记指纹差异，见第 12 节风险）。

### 6.4 前端

- 去掉 `id@version` 选择器；一个平台一张配置卡。
- 展示：平台名、当前实现大版本、实现指纹短码、最近更新时间、能力列表、旧大版本下线提示。
- “测试 / 推送生产”机制保留；推送的是配置，不包含实现版本。
- 绑定保存前调用 `probe`，失败时给出明确原因，不写入半成品配置。

## 7. Trace 重查协议

### 7.1 通用接口

```http
POST /api/v1/turns/{turn_id}/trace/refresh
```

流程：

1. 读取轮次与会话快照 `binding`；
2. `registry.resolve(adapter, major)`；
3. 若 `refresh_trace` 不在能力列表 → `400 CAPABILITY_UNAVAILABLE`；
4. 从 `usage.upstream_message_id`（其次从该轮 `metrics` 事件）取上游消息 ID；
5. 用 `config_source=current|original`（默认 current）、可选 environment 与 credential_ref 组装查询绑定；
   仅更新适配器 `trace_config_keys` 白名单字段（HiAgent 为 observe_base_url、observation_wait_s），调 `adapter.refresh_trace(...)`；
6. 事件以该轮 `turn_id` 追加，记录 trace_refresh 查询时间、凭据引用、环境存档、实现指纹与结果；
   仍不可用时保留已有明细与指标，不写推测值；
7. 更新 `latency_ms` / token / 调用次数与会话累计统计。

### 7.2 请求对象

```python
@dataclass
class TraceRefreshRequest:
    session_id: str
    turn_id: str
    binding: NormalizedBinding
    credential: Any
    message_id: str
    previous_usage: dict[str, Any]
    wait_s: float
```

### 7.3 历史兼容

- 新轮次必须把 `upstream_message_id` 写入 `usage`；已有轮次从事件里的 `metrics.upstream.message_id` 读取。
- 业务桥历史上把“已核验 Trace 用时”写在 `log.metric_source=actual_upstream_trace_timestamps` 里；平台只在“该轮没有适配器 binding”时做只读兼容，新代码不得再产生这种日志作为指标来源。
- 桥接会话（无 binding）在界面明确显示“桥接接入，不支持平台重查”，并引导迁移为平台适配器；不再假装可以重查。

## 8. 目录结构建议

```
backend/evalp/runtime/adapters/
  base.py                 # RunContext、PlatformAdapter、错误类型
  registry.py             # AdapterDefinition、resolve、指纹计算
  normalize.py            # 事件归一化与口径校验（唯一实现）
  platforms/
    openai/               # OpenAI 兼容
      adapter.py
      config.py
    hiagent/              # HiAgent 发布 API + Observe
      adapter.py
      sse.py              # SSE 帧解析
      mapper.py           # 事件映射
      trace.py            # Trace 查询与补齐
      config.py
    agentkit/
      ...
  legacy/                 # 仅保留只读兼容与迁移期包装，设下线日期
```

禁止：

- `runtime/adapters/**` 不得 import `evalp.services.*`、`evalp.mcp.*`、业务包或 SDK 业务代码。
- 不得存在运行时 `importlib` 动态替换函数、`patches/` 目录、按 agent 版本比较的分支。

## 9. 硬约束与自动化门禁

| 约束 | 门禁方式 |
|---|---|
| 适配器只做协议翻译 | 架构测试：扫描 `runtime/adapters/**` 的 import 白名单，发现业务/服务依赖即失败 |
| 禁止运行时补丁 | 架构测试 + CI grep：禁止 `patches/`、禁止对模块属性赋值替换函数、禁止动态加载业务模块 |
| 禁止按 agent 版本分支 | AST 扫描：适配器包内禁止出现与 `version` / `published_version` 的相等比较（`config` 原样透传除外） |
| 一个平台一个活跃大版本 | 注册表测试：同一 `adapter` 只能有一个 `sunset=None` 的实现；旧大版本必须有下线日期 |
| 契约样本必过 | `tests/contract/adapters/<platform>/` 回放真实 SSE / Trace fixture，断言规范事件摘要 |
| 归一化只做一次 | 所有适配器 fixture 共用一套 `assert_canonical_events`；适配器不得自带 token 汇总逻辑 |
| 绑定不含实现版本 | Schema 测试：新写入的 binding 不得出现 `version` 字段；旧数据可读 |
| Trace 可重查 | 每个带 `trace` 能力的平台必须有 `refresh_trace` 契约用例（成功、仍未就绪、身份不符） |

## 10. 迁移计划

### 阶段 0：盘点与样本（不改行为）

- 收集每个平台的真实脱敏 SSE / Trace 片段，建立契约 fixture。
- 列出 `integrations/hiagent` 与业务桥中被依赖的能力，标记“协议”与“业务”。

### 阶段 1：接口与注册表（向后兼容）

- 引入 `PlatformAdapter`、`AdapterDefinition`、`normalize.py`。
- `registry.resolve` 支持新旧 binding 读取；`validate_binding` 不再写死版本。
- `HiAgentAdapter` 拆为 `platforms/hiagent/*`；`integrations/hiagent/bridge.py` 标记 deprecated，不再接收新功能。
- 新增架构测试与契约测试骨架。

### 阶段 2：绑定与界面

- Pydantic `AdapterBinding` 删除 `version`；新增 `adapter` / `major`。
- 环境存档读取旧数据归一化；新写入新结构。
- 前端改为“一个平台一张卡”，展示实现指纹；去掉版本选择器。
- 会话快照继续冻结 `binding`；轮次记录 `adapter_fingerprint`；评测批次固定指纹。

### 阶段 3：Trace 重查能力化

- `refresh_trace` 改为适配器钩子；已落库消息 ID 的旧轮次可重查。
- 前端按钮对所有带 `refresh_trace` 能力的轮次可见；无能力的桥接会话显示明确说明。
- 移除会话服务里平台相关的 Trace 特殊分支。

### 阶段 4：业务桥迁移

- 把五阶段消费、AB 配置、输出契约迁到中间件 / 评估器 / 契约模块。
- 旧桥接入切到 `hiagent` 绑定；停用 `patches/` 与按版本复制的 release。
- 用合成历史会话验证：普通会话、Trace 补齐、Trace 重查、评测口径。

### 阶段 5：清理

- 删除/归档旧的按版本适配器包与补丁；保留一个只读迁移说明。
- `integrations/hiagent` 只保留示例或删除；平台侧只有 `platforms/hiagent` 一份协议实现。
- 补齐下线策略与告警。

## 11. 测试策略

- **契约测试**：真实帧 → 规范事件摘要（类型、step_id、usage、tool 配对、trace_status）。
- **口径测试**：整轮 token 与明细 token 不一致、工具重复、Trace 延迟、Trace 缺失、SSE 中断。
- **架构测试**：import 白名单、禁止 patch、禁止平台版本分支、一个大版本。
- **迁移测试**：旧 binding 读取、环境存档回放、会话快照兼容、评测批次指纹固定。
- **前端测试**：一个平台一张卡、指纹展示、重查按钮仅在有能力的轮次出现。
- **回归门槛**：任何适配器改动必须同时更新/通过对应平台的 fixture；否则 CI 失败。

## 12. 版本与下线策略

- `major` 只在平台 API 不兼容时递增；同一平台不允许两个活跃大版本。
- 旧大版本必须声明 `sunset`（建议不少于 30 天），到期后：
  - 新绑定不可选；
  - 旧绑定在保存/执行时返回明确错误；
  - 只读查询仍可看到旧配置与指纹。
- agent 版本、平台应用版本永远不进入适配器版本号。

## 13. 风险与未决问题

| 风险 | 处理 |
|---|---|
| 适配器统一升级影响历史评测复现 | 轮次记录 `adapter_fingerprint`；评测批次固定指纹并在报告中标注；必要时对差异批次重跑 |
| 平台 API 悄悄漂移 | `probe` 校验关键字段与 API 版本；契约 fixture 定期用真实环境回放（可手动触发） |
| 一个实现要兼顾多租户怪癖 | 用配置项与能力开关，不开分支副本；确实不兼容才升 `major` |
| 迁移期双实现并存 | 只允许 `legacy/` 只读包装，设明确删除日期；架构测试禁止新代码依赖 |
| 业务胶水迁移成本 | 按中间件/评估器能力逐项搬，先搬消费器与阶段校验，再搬 AB 配置 |

未决：

1. 评测批次进行中升级适配器时，是“继续当前实现并标记差异”，还是“暂停批次等待人工确认”？建议前者 + 报告标注。
2. `impl_digest` 以包内源码哈希计算，是否包含 `config.py` 的 Schema（建议包含）。
3. OpenAI 兼容适配器是否需要 `major` 概念（建议保留，未来 API 破坏性变更时使用）。
