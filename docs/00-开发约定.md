# 开发约定（所有开发者 / 子 agent 必读）

设计依据：`docs/01-概要设计.md`、`docs/02-详细设计.md`。**详设是唯一事实来源**。确需偏离时，在 `docs/DEVIATIONS.md` 末尾追加一节：`## <模块> — <简述>`，写明原因与影响。不要静默偏离。

## 1. 环境

- 仓库根：`/home/claude/evalp`
- Python 虚拟环境：`/home/claude/evalp/.venv`（`source .venv/bin/activate`）。依赖统一在 `backend/pyproject.toml` 声明，以 `pip install -e "backend[dev]"` 安装。**不要**并行改 pyproject；新增依赖时，在 DEVIATIONS.md 记录并告知总控。
- 代码需兼容 Python 3.11+（不要用 3.12+ 专有语法，如 `type X = ...`、PEP 695 泛型）。
- 前端：`frontend/`，npm，Node 22。构建产物输出到 `backend/evalp/static/`。
- 不要 `git commit`，总控审查后统一提交。
- 不要留下后台常驻进程；测试中启动的服务必须在测试结束时关闭。

## 2. 后端分层与共享约定

```
api/v1/<资源>.py   每个模块导出 `router = APIRouter(prefix=..., tags=[...])`；app 自动发现并挂载，无需修改 app.py
schemas/<资源>.py  Pydantic v2 DTO
services/<名>.py   业务逻辑，构造参数为 AppContext：`class AssetService: def __init__(self, ctx: AppContext)`
store/models.py    全部 ORM 模型（地基阶段一次性按详设 3.3 建全，后续模块只读不改；确需加字段→DEVIATIONS + 新 Alembic 迁移）
```

- **AppContext**（`evalp/context.py`）：持有 `config`、`db`、`blobs`、`bus`、`secrets` 等基础设施；`ctx.svc(ServiceClass)` 返回该服务的单例（懒加载缓存）。路由里用依赖 `ctx: AppContext = Depends(get_ctx)`。
- **数据库**：`async with ctx.db.read() as s:` 用于读；`async with ctx.db.write() as s:` 用于写（全局单写锁 + 事务，退出时自动提交，异常时回滚）。服务内直接用 SQLAlchemy 2.0 select / ORM。
- **ID**：`from evalp.ids import new_id; new_id("agt")` → `agt_01J…`（ULID）。
- **时间**：`from evalp.utils.time import now_iso`，UTC ISO8601，毫秒精度，以 `Z` 结尾。
- **错误**：`from evalp.errors import NotFound, Conflict, ValidationFailed, InvalidState, ...`，每个都带详设 11.2 的 code；全局异常处理器统一输出 `{"error":{code,message,details}}`。
- **分页**：`from evalp.api.pagination import Page, paginate`；参数 `limit`（默认 50，最大 200）+ `cursor`。
- **JSON 列**：ORM 中使用 `JSONText` 类型（自动序列化，`ensure_ascii=False`）。
- **日志**：`from evalp.logging import get_logger; log = get_logger(__name__)`。
- **规范化 JSON 与哈希**：`from evalp.utils.canonical import canonical_json, sha256_hex`（地基阶段提供基础实现，Spec 模块可以扩展）。

## 3. 测试

- 测试放在仓库根的 `tests/`：`unit/`、`integration/`、`contract/`、`e2e/`；pytest-asyncio 用 `asyncio_mode=auto`。
- `tests/conftest.py` 提供以下 fixture：`ctx`（临时数据目录 + 已迁移的数据库）、`client`（`httpx.AsyncClient` + ASGITransport，已带 token）、`app`。
- 测试中需要模型调用时，使用 `tests/fixtures/fake_openai.py`（运行时阶段提供），**禁止**调用真实模型服务。
- 每个模块交付时，`pytest tests -q` 必须全绿，`ruff check backend tests` 不能有错误。

## 4. 代码风格

- 用 ruff 做 lint 和格式化（行宽 110）；类型标注完整；公共函数写简短的中文 docstring。
- 标识符一律用英文；注释和用户可见文案用中文。
- 不要写占位实现（`pass`、`TODO`）然后宣称完成；做不完就在交付报告中如实列出。

## 5. 交付报告格式（子 agent 完成时返回）

1. 完成了什么（文件列表）
2. 与详设的偏离（并已写入 DEVIATIONS.md）
3. 测试结果（命令及通过数）
4. 遗留问题 / 给后续模块的接口说明
